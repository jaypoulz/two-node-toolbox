# Plan: `make status` unified dashboard (Phase 2)

## Context

There is no single command answering "what do I have running right now". `make info` prints
four lines of locally cached instance data; instance state, cluster state, VM states,
proxy container health, and cluster reachability each require separate manual steps spread
across the troubleshooting docs. This phase adds `make status`: a full-depth dashboard with
graceful per-section degradation, so it is useful whether or not the instance, VMs, or
cluster are reachable.

Depth decision: full by default (includes SSH probe of the hypervisor and a cluster API
probe via `proxy.env`), with every section independently skippable when its prerequisites
are missing or unreachable.

`make info` is folded into `make status`: the status output includes everything info
prints today (stack name, host IP, SSH user, Cockpit URL), and `make info` becomes an
alias for `make status` so existing muscle memory and docs keep working.

## Changes

### New file: `deploy/openshift-clusters/scripts/status.sh`

Placed alongside `deploy-cluster.sh`, which sets the precedent for scripts spanning
hypervisor and cluster concerns. Sources `deploy/aws-hypervisor/scripts/common.sh` for
`get_node_dir`, `get_shared_dir`, `msg_info`/`msg_warning`/`msg_err`, and env defaults
(`REGION`, `STACK_NAME`).

Design rules:

- Each section prints a clear PASS/WARN/SKIP-style status line.
- No global `set -e` around probes: a failing section reports and the script continues.
- Every network operation has an explicit timeout (`aws` CLI calls wrapped in `timeout`,
  `ssh -o ConnectTimeout=10`, `timeout 15` on the `oc` probe).
- Remote hypervisor checks are bundled into a single SSH round trip (one heredoc).

Sections:

1. **Local config** - presence of `aws-hypervisor/instance.env` and
   `openshift-clusters/proxy.env`. `inventory.ini` is reported informationally, never as a
   warning: it is only required for OpenShift deployment and is generated by
   `make inventory`, so when absent the line reads "not created yet - run 'make inventory'
   before deploying a cluster".
2. **EC2 instance** (absorbs `make info`) - stack name, public IP, SSH user, and Cockpit
   URL from instance-data files (same sources as `print_instance_data.sh`); live state and
   `LaunchTime` from `aws ec2 describe-instances`, with computed uptime and a reminder
   that metal instances accrue cost while running. If `aws-instance-id` is missing, report
   "no instance" and skip the remote sections.
3. **Cluster state file** - topology / installation_method / status from
   `instance-data/cluster-vm-state.json`, using `jq` with the grep fallback pattern already
   used in `startup-cluster.sh`.
4. **Hypervisor (single SSH round trip)** - reusing the probe snippets that already exist
   in `stop.sh` and `startup-cluster.sh`:
   - dev-scripts directory present,
   - cluster VM names and `virsh domstate` per VM,
   - proxy container: `podman ps --filter name=external-squid`,
   - BMC simulator when topology is fencing: `sushy-tools` container (dev-scripts) or
     `ksushy` user service (kcli).
   If SSH is unreachable, print one WARN line and skip the section.
5. **Cluster API** - if `proxy.env` exists: `source proxy.env && timeout 15 oc get nodes`
   summarized to Ready/NotReady counts. On failure, WARN with the existing
   restart-the-proxy troubleshooting hint (`podman restart external-squid`).

Ends with a hint suggesting `make doctor` (Phase 3) when configuration files are missing.

### Makefile (`deploy/Makefile`)

- New `status:` target invoking the script.
- `info:` becomes an alias for `status` (points at the same script);
  `print_instance_data.sh` is removed once its output is covered by status.
- `help` entry under "Instance Utils" describes status and marks info as an alias.

### Docs

- `deploy/README.md`: add to the command list, replace `make info` references where the
  dashboard is the better answer, and reference from the troubleshooting section (status
  is the first thing to run when access breaks).
- Root `README.md` and `CLAUDE.md`: update the quick-start command blocks
  (`make info` mentions become `make status`).

## Verification

No AWS account or live cluster is available in the implementation environment, so
end-to-end verification covers the degraded paths; the live-instance path reuses
already-proven probe snippets verbatim, which limits the untested surface:

- Run with no `instance.env`: clear guidance, no crash.
- `make info` and `make status` produce identical output (alias works); missing
  `inventory.ini` renders as the informational "run 'make inventory'" line, not a warning.
- Run with a fabricated `instance-data/` directory and state file: sections render, the
  AWS query WARNs on timeout/credential failure instead of aborting.
- Run with a fabricated `proxy.env` pointing nowhere: cluster API section WARNs with the
  proxy hint.
- `bash -n` and `hack/shellcheck.sh` pass on the new script.
- Flag in the PR that one run against a real instance is the remaining manual test.
